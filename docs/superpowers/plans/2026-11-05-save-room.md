# Save Room Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Recommended here: native execution with executing-plans; the tasks share a small content model.

**Goal:** Создать личный статический сайт Игоря с четырьмя проектами, тёплым ASCII-интерфейсом и публикациями из JSON.

**Architecture:** SvelteKit предварительно формирует главную и страницы проектов. Загрузчик JSON возвращает проверенную доменную модель; компоненты получают данные через props. FSD ограничивает зависимости, сервер и CMS не создаются.

**Tech Stack:** SvelteKit, Svelte, strict TypeScript, adapter-static, Zod, ESLint, Prettier, Steiger с FSD plugin, Vitest, Playwright, Vercel. При установке выбрать совместимые стабильные версии, сохранить lockfile; не переносить конфиги другой версии SvelteKit вслепую.

**Spec:** `docs/superpowers/specs/2026-11-05-save-room-design.md` (согласовано).

## Global Constraints

- Русский интерфейс, Save Room, автор Игорь; пять личных ссылок из спецификации.
- Один JSON на публикацию, обычные локальные изображения, без произвольного HTML в содержимом.
- Закреплённые выше остальных; внутри групп дата по убыванию, затем стабильный порядок.
- «Подробнее» в той же вкладке, внешние ссылки в новой. Непредоставленные URL означают отсутствие кнопки.
- Одна тёплая тёмная тема, моноширинный шрифт с кириллицей, ASCII-кнопки и разделители, спокойные hover/focus.
- Компоненты с props, загрузка отдельно; строгие проверки, без пустых слоёв FSD.
- Только демонстрационные материалы из указанных папок; не публиковать служебные JSON, архивы и скрипты.
- Перед production: форматирование, lint, Steiger, Svelte/TS, unit/e2e и build.

## Review Focus

1. У проекта нет deploy/source URL: рассказ остаётся доступным, не появляются пустые или ложные кнопки (task 2, 3).
2. Повреждённый JSON, неизвестный блок, неверная дата или потерянная картинка: сборка завершается понятной ошибкой с именем записи (task 1).
3. Одинаковые даты и закрепления: порядок стабилен после пересборки (task 1).
4. Узкий экран, длинный русский текст и масштабирование: нет горизонтального переполнения и обрезанных ссылок (task 2, 3).
5. Клавиатура и открытое изображение: Escape, удержание/возврат фокуса; неизвестный slug даёт 404 (task 3).

## File Structure and Contracts

- `content/projects/*.json`: четыре записи; `static/images/projects/<slug>/`: копии оптимизированных обложек и скриншотов.
- `src/entities/project/model/project.ts`: Zod-схемы и выведенные типы `Project`, `ContentBlock`, `ProjectImage`, `ProjectLink`.
- `src/entities/project/model/catalog.ts`: `parseCatalog(input: unknown[]): Project[]`, `sortProjects(projects: readonly Project[]): Project[]`; чистые функции.
- `src/entities/project/api/catalog.server.ts`: `getProjects(): Promise<Project[]>`, `getProject(slug: string): Promise<Project | undefined>`; чтение файлов, проверка ресурсов, кеш в рамках сборки. Server entry `src/entities/project/server.ts`; типы и UI через `src/entities/project/index.ts`, без реэкспорта server-модуля в клиент.
- `src/entities/project/ui/ProjectCard.svelte`, `ProjectCover.svelte`, `ProjectBody.svelte`: визуализация доменной модели.
- `src/shared/ui/AsciiLink.svelte`, `AsciiDivider.svelte`, `ImageViewer.svelte`: независимые элементы и доступный просмотр изображения.
- `src/shared/config/profile.ts`: имя, черновое приветствие, временный аватар, пять ссылок.
- `src/widgets/intro/ui/Intro.svelte`, `src/widgets/project-feed/ui/ProjectFeed.svelte` и публичные `index.ts`.
- `src/routes/+layout.svelte`, `+layout.ts`, `+page.server.ts`, `+page.svelte`, `projects/[slug]/+page.server.ts`, `projects/[slug]/+page.svelte`, `+error.svelte`: тонкие точки интеграции SvelteKit, prerender и метаданные.
- `src/shared/styles/global.css`: токены темы, reset, типографика; локальный шрифт в `static/fonts/` с лицензией.
- `scripts/validate-content.ts`, `tests/content.test.ts`, `tests/site.spec.ts`: проверка контента и пользовательских сценариев.
- `package.json`, lockfile, конфиги SvelteKit/Vite/TS/ESLint/Prettier/Steiger/Vitest/Playwright, `.github/workflows/verify.yml`, `README.md`.

Модель: `Project { id, slug, title, summary, publishedAt, order, pinned, cover, links, body }`. Дата `YYYY-MM-DD`, `order` целое, `pinned` boolean. `ProjectImage { src, alt, caption? }`; `ProjectLink { kind: 'project' | 'source', label, href }`. `ContentBlock` — discriminated union по `type`: paragraph/text, heading/text, list/items, image/src/alt/caption. Heading отображается как h2; h1 принадлежит странице. JSON не содержит JSX, HTML или кода. Текст всегда экранируется стандартным рендерингом Svelte.

## Task 1: Проверяемый каталог и статический маршрут

**Files:** конфиги, модели/загрузчик, content, static images, validate-content, tests/content.test.ts, маршруты без окончательного визуала.
**Consumes:** утверждённая спецификация и файлы материалов.
**Produces:** типы и функции каталога выше; четыре заранее сформированные страницы и главная.

- [ ] Проверить git/инструкции репозитория; сохранить документацию базовым коммитом и создать рабочую ветку. Не заменять появившиеся пользовательские файлы. Прочитать навыки Svelte и использовать официальный MCP при реализации компонентов.
- [ ] Настроить минимальный совместимый SvelteKit static проект, TypeScript strict, unit runner и lockfile. Привязать FSD к `entities/widgets/shared`; маршруты оставить адаптерами фреймворка. Настроить Steiger без глобального отключения проверок; нужные исключения объяснить.
- [ ] Добавить тесты каталога: `expect(sorted.map(p => p.slug)).toEqual(['pinned-old', 'new', 'same-a', 'same-b'])`; `expect(() => parseCatalog([invalidDate])).toThrow()`; такие же проверки неизвестного type, duplicate slug/id, unsafe href, пустого alt и отсутствующей картинки через загрузчик.
- [ ] Запустить `npm run test:unit` и получить ожидаемые ошибки отсутствующих реализаций.
- [ ] Реализовать схемы, сортировку pinned/date/order/slug и загрузчик. Разрешить внешние HTTP(S)-ссылки, изображения только внутри `/images/projects/`; исключить выход за каталог. Ошибка содержит файл и путь поля. Валидировать реальную календарную дату.
- [ ] Скопировать нужные материалы по спецификации, оптимизировать без потери читаемости; написать четыре JSON. ВДА: Telegram; Dogs: сайт+source; Dog Day Afternoon и GLYPH/LAB: пустой links. Разделить статьи на естественные абзацы и изображения, не выдумывать достижения автора.
- [ ] Пререндерить `/` и `/projects/<slug>/`, настроить неизвестный slug как 404. `getProjects` возвращает полный каталог только на сервере; на главную передавать карточные данные без body, на страницу проекта — одну запись.
- [ ] Проверить `npm run test:unit`, `npm run validate:content`, `npm run check`, `npm run lint:arch`, `npm run build`. Ожидание: exit 0 и HTML четырёх статических страниц.
- [ ] Закоммитить законченный каталог и статические маршруты.

## Task 2: Главная и визуальная система

**Files:** shared UI/styles/profile, widgets, ProjectCard/ProjectCover, layout, home route, tests/site.spec.ts.
**Consumes:** проверенные записи и карточные данные task 1.
**Produces:** адаптивная главная; `ProjectCover` props `{ image: ProjectImage }`, `ProjectCard` props `{ project: Omit<Project, 'body'>, reverse: boolean }`; `Intro` берёт profile через props, `ProjectFeed` получает массив карточных данных.

- [ ] Добавить браузерный сценарий: четыре карточки, пять личных ссылок, ссылки ВДА и Dogs, отсутствие внешней кнопки у остальных; после тестового запуска убедиться, что отсутствующий интерфейс даёт FAIL.
- [ ] Реализовать тему: ориентиры CC-29 `#212123`, `#80493a`, `#e5ceb4`, `#b2b47e`; итоговые контрастные сочетания проверить визуально. Выбрать локальный лицензированный моноширинный шрифт с кириллицей. Рамки и символы не заменяют семантику HTML.
- [ ] Собрать вступление с временным аватаром-ботом и пятью ASCII-ссылками; ленту с чередованием сторон. На узком экране — обложка сверху. Обложки квадратные и без обрезки значимого текста; размеры зарезервировать для стабильности макета.
- [ ] Добавить в e2e `expect(await page.evaluate(() => document.documentElement.scrollWidth <= innerWidth)).toBe(true)` при 360px, длинном заголовке и увеличенном тексте; проверить клавиатурный фокус и target внешних ссылок.
- [ ] Выполнить `npm run test:e2e`, проверить скриншоты 360px и 1440px, привести визуал к тёплому минимализму из спецификации. Показать первую работающую версию Игорю для дальнейших правок.
- [ ] Закоммитить главную и визуальные компоненты.

## Task 4: Проверки, публикация и инструкция автору

**Files:** package scripts, .github/workflows/verify.yml, README, deployment config.
**Consumes:** рабочий сайт tasks 1–3.
**Produces:** воспроизводимая установка, единый verify и публикация после проверок.

- [ ] Настроить `npm run verify`: format check, ESLint с max-warnings 0, Steiger, Svelte/TS, content validation, unit, build. E2e отдельно в CI после сборки. Использовать одну закреплённую поддерживаемую Node-версию локально/CI/Vercel.
- [ ] Настроить GitHub checks на pull_request и main. В Vercel build command использовать `npm run verify`, поэтому даже прямой push не публикует сборку с проваленными локальными проверками. E2e — обязательная проверка перед merge; возможность защиты ветки проверить при настройке GitHub.
- [ ] README: команды установки/разработки/проверок, пример JSON, добавление картинки, изменение даты/закрепления/аватара и внешних ссылок, настройка Vercel static output и origin. Отдельно объяснить, что публикация не меняет приватность исходных проектов.
- [ ] Проверить чистую установку `npm ci`, `npm run verify`, `npm run test:e2e`. Выполнить ревью по стандартам и спецификации, устранить существенные замечания.
- [ ] Подключить Vercel, если доступен действующий доступ; если нужна авторизация владельца, подготовить точный шаг для Игоря после готовности проверенного сайта. Не выдавать локальную сборку за выполненный деплой.
- [ ] После публикации проверить главную и четыре страницы по URL, изображения, ссылки, метаданные и мобильный вид. Зафиксировать результат и оставшиеся заменяемые материалы.
